## Торговые функции (Высокий приоритет)

### 3. Ручной риск в команде (Высокий приоритет)
- [ ] Добавить возможность указывать риск вручную в команде: `50 l xrp 500 2.5`
  - **Синтаксис:** `<risk$> <dir> <symbol> <usd> <price> [preset]`
  - **Реализация:**
    - Модифицировать `CommandParser.ts` → расширить парсинг для команды `l/s`
    - Если первый аргумент число > 1000 ИЛИ есть $ в конце → считать риском
    - Иначе первый аргумент = ticker (текущее поведение)
  - **Время:** 1-1.5 часа
  - **Примеры:**
    - `50 l xrp 500 2.5` - риск $50, использовать пресет по умолчанию
    - `l xrp 500 2.5` - текущее поведение (риск из пресета)
    - `50$ l xrp 500 2.5` - альтернативный синтаксис с явным указанием

### 4. Настройка плеч (Леверидж)

  - **Синтаксис:**

    - `lev <multiplier> <symbol>` - установить плечо на конкретный символ

  - **Хранение:**
    ```json

        "XRP/USDT": 10,
        "BTC/USDT": 20
      },
      "default": 10
    }
    ```
  - **Время:** 2-3 часа

### 5. Ручной SL после входа
- [ ] Добавить возможность ставить SL вручную после входа
  - **Синтаксис:** `sl <symbol> <price>` или `sl <symbol> -5%` (относительно entry)
  - **Реализация:**
    - В `engine.ts` добавить обработку команды `sl`
    - Использовать `ex.createStopMarketClose` с указанной ценой
    - Снять текущий SL перед установкой нового
  - **Примеры:**
    - `sl xrp 2.4` - установить SL на $2.4
    - `sl xrp -3%` - установить SL на 3% ниже entry
  - **Время:** 1 час

### 6. Трейлинг стоп (Trailing Stop)
- [ ] Реализовать трейлинг стоп на последнюю TP (самую дальнюю)
  - **Логика:**
    - Трейлинг активируется при достижении определенного R (риск-прибыль)
    - Например: при R = 7, trailing = 2, SL на 3% → начинаем двигать SL на расстоянии 6% от текущей цены
    - Формула: `trailingDistance = currentTrailMultiplier * originalStopDistance`
  - **Синтаксис в пресете:**
    ```json
    {
      "trailing": true,
      "trailing_activation_r": 7,  // начинать трейлинг при достижении 7R
      "trailing_multiplier": 2     // держать SL на расстоянии 2x от original SL
    }
    ```
  - **Реализация:**
    - В фоновом обработчике задачи проверять условие активации
    - При активации начинать двигать SL следом за ценой
    - Обновлять SL не чаще чем раз в N секунд (например, 30 сек)
  - **Время:** 4-5 часов (сложная логика)
  - **Приоритет:** Средний

### 7. Лимитные заявки (отложенные ордера)
- [ ] Добавить команду для быстрого выставления лимиток
  - **Синтаксис:** `limit <dir> <symbol> <usd1> <price1> [<usd2> <price2> ...]`
  - **Примеры:**
    - `limit l xrp 500 2.35` - одна лимитка long на 500$ по $2.35
    - `limit s btc 1000 45000 2000 44800` - две лимитки short
  - **Реализация:**
    - Расширить `CommandParser.ts` для команды `limit`
    - Использовать существующую логику `computeQtyForUsdSmart`
    - Создавать только LIMIT ордера (не STOP)
  - **Время:** 1-1.5 часа
  - **Примечание:** Полезная фича для более опытных трейдеров

### 8. Вход без пресета (отложкой и лимитами)
- [ ] Разрешить вход без пресета: `l xrp 500 2.5 -` или `--no-preset`
  - **Синтаксис:** `l <sym> <usd> <price> -` (прочерк означает не использовать пресет)

### 9. Копитрейдинг (Сложная фича)
- [ ] Реализовать копитрейдинг между аккаунтами
  - **Логика:**
    - Один "мастер" аккаунт делает сделки
    - Один или несколько "фоловер" аккаунтов копируют сделки
    - Разные объёмы и риски на каждом аккаунте
  - **Настройка (в config/copy_trading.json):**
    ```json
    {
      "master": "main_account",
      "followers": [
        {
          "account": "copy_account1",
          "volume_multiplier": 0.5,  // 50% от размера мастер-сделки
          "risk_multiplier": 0.5     // 50% от риска
        }
      ]
    }
    ```
  - **Реализация:**
    - После создания сделки на мастере → триггерить копирование
    - Для каждого фоловера рассчитать объём и риск по мультипликаторам
    - Выполнить ту же самую команду на фоловер-аккаунте
    - Важно: логировать все копируемые сделки
  - **Время:** 8-10 часов (очень сложная фича)
  - **Приоритет:** Низкий, реализовать после всех основных фич
  - **Риски:** Сложная отладка, нужно много тестов
