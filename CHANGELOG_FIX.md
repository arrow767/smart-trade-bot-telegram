## 🎯 Цели исправлений

## ✅ Реализованные изменения

### 1. **Защита от market-исполнения LIMIT ордеров** ⚠️ КРИТИЧНО

**Проблема:** Если цена двигалась между проверкой и размещением LIMIT-ордера, он мог оказаться на неправильной стороне и исполниться немедленно как market.

**Решение:**
- Добавлены функции `isValidLimitPrice()` и `safeEntryOrderType()` в `src/core/TradingUtils.ts`
- Перед размещением LIMIT всегда проверяется актуальная цена
- Если LIMIT окажется на неправильной стороне → автоматически используется STOP_MARKET с буфером
- Никогда не создаётся market-ордер для отложенных входов

**Файлы:**
- `src/core/TradingUtils.ts` (строки 91-124)
- `src/core/engine.ts` (строки 767-793, 511-542)

---

### 2. **Улучшенный учёт minNotional при дроблении**

**Проблема:** `minNotional` не всегда правильно учитывался при расчёте минимального объёма ноги.

**Решение:**
- Исправлена функция `calcBoundsUsd()` — теперь `minUsd = max(minQty * price, minNotional)`
- Дробление учитывает leverage brackets при включённом `SPLIT_ALIGN_TO_CURRENT_LEV`

**Файлы:**
- `src/core/engine.ts` (строки 85-105)

---

### 3. **Контроль дальности заброса отложек** 🆕

**Решение:**
- Добавлена переменная окружения `MAX_ENTRY_DISTANCE_PCT` (по умолчанию 15%)
- При размещении отложки дальше этого расстояния от текущей цены выводится предупреждение
- Не блокирует размещение, но предупреждает пользователя

**Переменные окружения:**
```env
MAX_ENTRY_DISTANCE_PCT=15  # Макс расстояние отложки от цены (%)
```

**Файлы:**
- `src/core/engine.ts` (строки 61-62, 761-765)

---

### 4. **Исправление трекинга множественных задач** ⚠️ КРИТИЧНО

**Проблема:** Если несколько задач работали с одним символом, они могли "видеть" чужие ордера/позиции и преждевременно удалять свои tasks.

**Решение:**
- Добавлены методы в `TaskBook`: `getBySymbol()`, `getAllEntryOrderIdsBySymbol()`
- При проверке flat-позиции теперь учитываются другие задачи на этот символ
- Задача удаляется только если:
  - Позиция flat
  - У неё нет входных ордеров
  - У других задач на этот символ тоже нет активных входов

**Файлы:**
- `src/core/TaskBook.ts` (строки 145-159)
- `src/core/engine.ts` (строки 896-914, 1041-1057)

---

### 5. **Автоочистка старых tasks с ошибками** 🆕

**Решение:**
- При старте `TaskBook` автоматически удаляет tasks со `status=error` старше N дней
- Конфигурируется через `AUTO_CLEANUP_ERROR_TASKS_DAYS` (по умолчанию 3 дня)

**Переменные окружения:**
```env
AUTO_CLEANUP_ERROR_TASKS_DAYS=3  # Автоудаление tasks с error старше N дней
```

**Файлы:**
- `src/core/TaskBook.ts` (строки 23-45)

---

### 6. **Проверка и удаление висячих tasks** 🆕

**Решение:**
- Добавлен метод `cleanupOrphanTasks()` в `TaskBook`
- Каждые 30 секунд в фоновом обработчике проверяются tasks:
  - Если отложек нет на бирже
  - И позиция flat
  - → Задача удаляется
- Предотвращает накопление "мёртвых" tasks

**Файлы:**
- `src/core/TaskBook.ts` (строки 161-197)
- `src/core/engine.ts` (строки 824-844)

## 🔧 Что изменилось в логике

### Дробление позиций

**Было:**
- Использовался `SPLIT_ENTRY_USD_MAX=200000` как жёсткий лимит

**Стало:**
- Автоматический расчёт на основе:
  - `minNotional` из фильтров
  - `notionalCap` из leverage brackets для текущего плеча (если `SPLIT_ALIGN_TO_CURRENT_LEV=1`)
  - Динамическое дробление больших позиций с учётом реальных ограничений биржи

### Размещение отложек

**Было:**
- Проверка `isLimit` один раз
- При ошибке fallback на LIMIT (мог исполниться как market)

**Стало:**
- Всегда актуальная проверка цены перед размещением
- Безопасный выбор типа ордера (LIMIT или STOP_MARKET)
- Fallback только если цена безопасна

## ⚠️ Критические моменты

1. **НИКОГДА не используется `createMarketEntry` для отложенных входов** — только LIMIT или STOP_MARKET
2. **Всегда проверяется актуальная цена** перед размещением LIMIT
3. **Учитываются другие задачи** на тот же символ при удалении task
4. **Периодическая очистка** старых и висячих tasks для предотвращения "мусора"

## 🧪 Тестирование

Рекомендуется протестировать:

1. **Отложки при быстро движущейся цене:**
   - Создать отложку long выше текущей цены → должна стать STOP_MARKET
   - Создать отложку short ниже текущей цены → должна стать STOP_MARKET

2. **Множественные задачи:**
   - Создать 2-3 задачи на один символ
   - Снять отложки одной задачи вручную
   - Проверить, что другие задачи не удалились

3. **Автоочистка:**
   - Создать task, перевести в `status=error`
   - Изменить `updatedAt` на 4 дня назад
   - Перезапустить бота → task должен удалиться

4. **Дробление больших позиций:**
   - Попробовать вход с большим объёмом (например, 500k USD)
   - Проверить, что дробление происходит корректно
   - Убедиться, что не создаётся market-ордер
